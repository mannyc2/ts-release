# Browserbase engineering requirements audit

> Historical peer-standards snapshot, captured on 2026-09-26 at the revisions below. Normative clauses and observed enforcement are evidence for the plan, not claims that ts-release has adopted every requirement. See [current implementation status](implementation-status.md) for the bounded milestone, actual verification and remaining work. These are task research documents, excluded from published packages.

Audited 2026-09-26. This report separates contributor requirements, enforcement implemented in source, and observed implementation choices. It is a standards audit with selected implementation checks, not a claim that every production function or every historical test complies.

The major omission in the earlier review was the repository's engineering system: inherited contributor instructions, simplification and test-selection policy, patched Effect diagnostics, package-boundary enforcement, strict installed consumers, and source-bound acceptance evidence. Copying a few resource and function patterns does not adopt that system.

## Where the implementation qualifies the ideal

1. **Strict policy does not mean no exceptions.** `Definitions.describe` has three reasoned unsafe-assertion exceptions around Effect AI Tool cloning and its generic name/type relation; Session has one preserving the supplying lifetime's release success type. The requirement is reviewed necessity and no coercion across untrusted-data boundaries, not a blanket “no casts exist” claim. [Definitions:307–325][B-cast-example], [Session:410–414][B-cast-session]
2. **The Promise exception is path-based and broad.** It covers `internal/browser/**/*.ts`, including the large owner Session module, not only a tiny leaf Playwright adapter. Tests/examples/hosted have separate relaxations. A transfer plan should identify the actual native bridge per file rather than copy that broad allowance. [lint:151–197][B-lint-exceptions]
3. **Simplicity is a review duty, not an achieved size limit.** At pinned main, owner Session has 1,903 lines, scripted Engine 1,992, Tool Handlers 530 and Host 459. These are review targets, not proof of a defect; no complexity threshold was found. The transferable standard is reducing unnecessary mechanisms while preserving required ownership, not recreating those file shapes.
4. **Functional purity means explicit effects and boundaries, not eliminating all mutation.** Scripted sessions use owned Maps/counters; production owner bookkeeping is mutable. `sideEffects:[]` describes import-time behavior. It does not certify every function is mathematically pure or prevent incorrect lifetime handling. [Testing:69–112][B-testing], [upstream TOOLCHAIN:Exports and entry points][U-toolchain]
5. **Dependency injection is more specific than “provide layers at the boundary.”** Layer construction captures configuration/dependencies, often without allocation. Operation Scope still belongs to its caller. Browserbase account composition intentionally retains shared Client/Sessions services; it does not open a browser. This avoids repeated authentication composition and prevents service lifetime from swallowing caller scope. [Client:31–105][B-client], [Account:38–72][B-account], [agent guide:75][B-agent-layers]
6. **Schema-first does not remove resource guards.** Transport scans maximum JSON nesting before structured decoding, bounds bytes, validates exact allowed origins, and models mutation outcomes. Those checks are authority/resource contracts, not automatically redundant hand parsing. [Transport:14–16,70–111,178–210][B-transport]
7. **Not all existing tests embody the newer selection policy.** The suite contains regex checks of configuration and a runtime boolean wrapper for compile-time proofs. Their existence alone is not permission to duplicate that machinery. Necessity/provenance and stronger retained proof require individual review. This audit does not infer test-first history from present files. [lint-policy test][B-policy-test], [workflow-types:79–88][B-types], [testing selection][U-selection]
8. **Guidance can drift.** CONTRIBUTING:66 describes the coordinated current version as beta.2, while main manifests carry beta.3 and root README explains main can be ahead of publication. CONTRIBUTING:62 says “four projects,” while its referenced ownedProjects map has three public projects. These minor discrepancies are reasons to verify prose against executable configuration, not reasons to discard the standards. [CONTRIBUTING][B-packages], [policy test:35–39][B-policy-test]
9. **Public owner supervision and optional callbacks have different contracts.** Browser.scoped explicitly contains callback construction and preserves the body's/cleanup's cause within its workflow. Optional cleanup notification is separately contained and cannot claim cleanup confirmation. The prior audit's ContextCoordination construction-throw defect remains an implementation departure, not a pattern to reproduce; no new reproduction was run here. [Browser:288–297][B-scoped], [browser guide:108–122][B-owner-guide]
10. **Observed local evidence has limits.** Scripted/native suites cannot qualify live hosted behavior. Published version, source-main version, engine ranges and verified runtime pins are separate facts. The same discipline should apply to ts-release's npm/Sigstore/GitHub compatibility claims. [CONTRIBUTING:19,70][B-packages], [RELEASING:64][B-release]

## Verification performed and remaining limits

The existing, dependency-free `tools/test/lint-policy.test.mjs` was executed with pinned Node 24.14.1 and `npm_config_offline=true`: all six tests passed. The first sandboxed attempt failed at its read-only `git ls-files` subprocess with EPERM; the allowed retry outside the sandbox passed. That verifies the policy/configuration alignment checks on the current clean checkout. It is not a new full library lint, native, packed-consumer, or full acceptance result.

The source audit inspected the complete root contributor instruction chain, inherited AGENTS, inherited simplify/testing policy and relevant references, complete installed Effect AGENTS, lint/preset/compiler policies, acceptance/CI wiring, package manifests and representative service/ownership/testing/transport implementations. Package guides were read for relevant ownership, service, error, test, public-API and evidence sections; product-specific browser features are outside this standards audit. Remote repository settings/protected environments and current full CI success were not certified. No consumer implementation, dependencies, branches, or runtime state were modified.

The next ts-release plan should be judged against BB-S01–BB-S36 and corresponding Reactor requirements, with each requirement marked adopted, consciously adapted, or deferred for a stated reason. Existing lifecycle fixes can be retained when justified, but they do not complete that adoption.
