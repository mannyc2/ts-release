## Decisions

Keep the provider-specific refusal, recovery, byte-ownership, and independent native-consumer proofs listed below. The generic external-provider integration does not replace concrete npm, GitHub, Python, catalog, or Apple protocol rules. Packed import/authoring checks do not replace dispatch/recovery behavior. Conversely, an in-memory owner test does not establish installed package closure, real process loss, or foreign interpreter behavior.

There are two accepted deletion/consolidation decisions and one explicitly deferred grammar overlap:

1. **Accepted and implemented by the coordinator: delete the fixture-only assertion at `catalog/render.test.ts:18`.** `expect(cell).toMatch(...)` checks a key obtained from `Object.entries(f.formula.archives)`, not renderer output. Keep the URL/digest occurrences, exact Scoop selectors/metadata, and Ruby installation/test snippets. Native Homebrew selection also checks all four actual output branches. Removing this assertion loses no production behavior proof; the loop can use values once `cell` is unused.
2. **Accepted and implemented by the coordinator: consolidate shared GitHub transport preparation in the existing packed owner.** `github/authority.test.ts:15–37` only prepares one request, counts one credential callback, and checks omitted framing headers. `github/packed-consumer.mjs:44–140` already authors all four annotated/lightweight × zero/three-asset graph shapes, loads them through public definitions, prepares the first operation through the actual shared transport with the real GitHub authorization function, asserts exactly one owner, and proves zero registry reads. `check-packed-npm.ts --catalog` executes this from physical Bun/npm installations under Node/Bun. The packed transport would refuse provider-owned framing; `github/wire.test.ts:84` separately asserts its absence. The packed catalog profile remains the required qualification for changes to this boundary. This is consolidation into existing evidence, not a new suite. Keep the other three authority cases.
3. **Retain npm grammar cases unchanged in this slice; further consolidation is deferred.** `npm/Native.ts:15` re-exports public HTTP `decodeJson` directly as `parseJson`; there is no npm parser wrapper to prove. The negative rows in `npm/authoring.test.ts:36` largely repeat `npm/large-body-consumer.mjs:12–60`, which already exercises that exact public function under both runtimes. Its `1.0` lexical-number refusal and positive `__proto__`/mixed-value object are not exact duplicates. The coordinator decided that this small partial overlap does not justify moving tests now. No parser harness, new assertion, additional matrix, or test relocation is authorized by this decision. The actual tarball corruption case at line 17 also remains an npm owner case.

I found no justified whole-file deletion. Other possible consolidation is conditional on the core/native owner's separate review; do not infer that the cross-products below are all redundant from their dimensions alone. No timing comparison was performed, so this review makes no quantitative performance claim.

The packed artifact qualification is an additional owner, not a replacement unit suite:

- `check-packed-artifacts.ts` first imports portable entries without optional peers, then physically installs retained producer packages and checks exact dist bytes/declarations. Both managers and runtimes call real producer consumers.
- `executables.mjs` adopts thirteen actual compiled outputs after producer deletion; only three Linux x64 GNU outputs execute. Cross-target format/metadata construction is not macOS/Windows/arm64/musl execution.
- `archives.mjs` independently lists/extracts ZIP/TAR with native tools, checks exact paths/modes/normalization, symlinks, PAX/trailing-space names, LFS pointer and submodule boundaries, and executes extracted CLI. Its invalid paths prove typed refusal before an output appears.
