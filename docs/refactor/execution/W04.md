## Implemented HTTP boundary

Public Node/Bun entries provide `makeHttpTransport`, `makeHttpRead`,
`makeCredentialExchange`, `makeGithubOidcTokenSource` and
`makeGithubTrustedPublisherHost`. The neutral HTTP entry provides explicit exact
credential-route composition. One provider must own the complete immutable
request before credentials are acquired; captured preparation returns no dispatch
permission. Only the unchanged kernel's fresh journal CAS invokes that send.

The native implementation pins Undici8.10.1. Its narrow Client and connector
entrypoints avoid Bun1.3.14's incomplete `undici` shim and unrelated full-entrypoint
Web API initialization failure. Their type adapters describe the inspected exact
implementation, including the connector's pending-socket return omitted by its
public type. These internal package paths are not claimed as semver-stable APIs.
The dependency is a real shipped maintenance/runtime cost, not hidden owned logic.

Each send has one dedicated HTTP/1.1 client, no interceptor/global dispatcher,
`idempotent:false`, `pipelining:0`, HTTP/2 disabled and connection reset. It never
follows a redirect or replays a write. The total deadline covers native DNS,
connection, headers and body; user credential and provider callbacks retain their
own execution bounds. Body bytes, admitted header fields and total decrypted
native input are separately bounded. The optional total-input limit defaults to
twice the body limit plus64KiB. Counting precedes the parser, so discarded header
whitespace, chunk extensions and trailers cannot evade that limit. Cleanup owns
the socket from creation, aborts even an unfinished TLS handshake, clears timers
and awaits close. Errors contain fixed diagnostics without credential bytes.

Raw header pairs are preserved before singleton admission. Node's `headers`
projection dropped duplicate Content-Type; Bun's `rawHeaders` already merged them.
Both defects were reproduced before choosing the maintained native dispatcher.
The separate Node socket peer also avoids Bun's server-shim missing close event.

GitHub OIDC checks public host facts before either runner credential read,
restricts runner bearer delivery to canonical HTTPS GitHub Actions service hosts,
reacquires tokens, and checks native RS256 signatures against issuer-owned JWKS,
exact requested/host claims and clock bounds. It does not reconstruct `sub`:
both legacy and immutable GitHub subject formats remain available to the actual
provider policy. The fixed issuer/JWKS/algorithm match live
[GitHub discovery](https://token.actions.githubusercontent.com/.well-known/openid-configuration).
Runner endpoint provenance is supported by the
[Actions runner source documentation](https://github.com/actions/runner/blob/main/docs/checks/actions.md).
Hosted positive grants and native provider policies remain Plan009 acceptance.

## Native Git implementation and review

The neutral `./git` entry owns catalog inputs, immutable intents, canonical object
sets, authoring and provider evidence. Node/Bun entries now provide
`makeGitCatalogHost` and `openGitJournal`. The shared native process boundary uses
private bare repositories, exact executable/argv, bounded output, interruption,
explicit credentials, disabled hooks/helpers/redirects, strict transfer checking,
and SHA-1/SHA-256 object formats. Captured object bytes and managed paths are
verified before journal uncertainty. Multiple intents can share an authority;
multiple independent authority pairs compose through the existing protected core
mechanism. Prepared sends compare complete immutable request facts and exact argv.
Only exact native push status lines enter receipts; arbitrary stdout is discarded.

The journal reads a fresh remote ref and validates one-parent history with exactly
one canonical event blob per commit. Preparation and publication scopes share one
global revision sequence. Equal native pushes return AlreadyRecorded for Git's
'=' response, never Appended. Lost or rejected push responses remain ambiguous;
only the common executor's same-live exact readback can continue a send.

Focused native evidence after corrections: 27 tests / 253 assertions passed across Git journal,
host, objects, process, and kernel Git/preparation suites. This includes actual
SHA-1/SHA-256 object graphs; deterministic managed-tree edits; deleted builder
repositories; independent caches and authorities; exact 1 MiB journal events;
malformed/merge/duplicate history; deliberately scheduled equal real Git pushes;
and lost native push responses with one same-live send and no restart resend.
These are disposable native Git repositories and a protocol send witness, not
hosted GitHub or native Windows/macOS acceptance. The first focused run exposed
an incorrect test assumption that recovery would not append fresh observations;
the test now checks no new DispatchStarted and exact observation-only suffix.

Independent reviewer `review_beta_declaration` closed both material findings:
credential resolver errors escaping unchanged, and loss of unrelated empty trees.
Both host and journal share one sanitized credential boundary; interruption is
preserved. Full native tree entries are grafted and compared, preserving empty
trees inside and outside edited ancestors. The original malicious native-valid
graph is rejected at managed-commit admission. Independent final tree controls
passed 3 tests/50 assertions. Native text decoding produces typed admission
failure, and post-push parse failure remains an ambiguous journal result.
See [W04-review.md](W04-review.md) for exact review scope and limits.

Git 2.43.0 enables optional netrc lookup in its
[actual HTTP source](https://github.com/git/git/blob/v2.43.0/http.c#L938).
The subprocess has private credential/config homes because omitting HOME alone
allows account-home fallback. This changes only the child environment. The newer
NETRC environment override is also set to an empty source; curl documents that
[it was added in 8.16.0](https://curl.se/libcurl/c/libcurl-env.html), so the installed
8.5.0 library cannot rely on it alone. Agent and parent environments are unchanged.

The native fetch has a process deadline; command output and decoded history are
bounded. These limits do not cap fetched-pack wire bytes or temporary-disk usage.
Linux process groups are killed and awaited on timeout/interruption, including
grandchildren. No Windows/macOS process-lifecycle acceptance is claimed.
