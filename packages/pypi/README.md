# @mannyc1/ts-release-pypi

Explicit per-file publication to PyPI, TestPyPI and compatible Python indexes.
This package is an unpublished release candidate component.

An owned wheel or sdist supplies its own native metadata. `inspectDistribution`
returns the facts needed by `WheelUpload` or `SdistUpload`; `upload` authors one
immutable operation. `author` expands a selected set after duplicate admission.
`definitions({ ...artifacts, read })` installs native multipart and Simple API
handling in the common Host. Token and trusted-publisher credentials remain live
through `authorizeToken` or `authorizeTrusted`, scoped to the exact request.

Simple JSON and HTML observations retain exact filename, SHA-256 and any native
size or yanked state. Absence after response loss grants no resend permission.
Compatible endpoints explicitly carry no inherited Warehouse duplicate law.
Pinned pypiserver 2.4.1 and devpi-server 6.20.3 have local native two/four-file
upload, process-restart and clean pip consumer witnesses. Hosted PyPI/TestPyPI,
trusted publishing and final release certification remain open.

Metadata admission uses the pinned native packaging 26.3 / SPDX 3.27.0 catalog.
The catalog is generated data with explicit source identity; parser logic and
catalog bytes are both included in maintenance accounting. Archive reads are
bounded to 128 MiB, metadata to 1 MiB and individual header values to 16 KiB
(description/license bodies use the metadata bound). ZIP64 is not admitted.
Named Unicode escapes in Python markers and segmented RFC2231 charset/variant
parameters require a future qualified reader; no executable metadata is evaluated.
